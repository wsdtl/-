# 游戏外工具边界

`tools/` 负责正式游戏之外的开发辅助工作：内容生成、全库校核、评分计算、平衡模拟和维护报告。

## 架构审查

`架构审查/` 只保存代码目录、文件命名、模块归属和分类声明等开发规范检查。`校验命令目录.py` 会主动加载全部正式命令，核对每条命令是否位于 `game/cmd/通用`、`专属` 或 `后台`，并确认声明的 `scope` 与目录一致；它只能由维护者手动运行，不参与游戏启动。

影响真实运行正确性的检查不放在本目录：命令唯一性、数据库状态唯一归属和守卫引用属于 `game/startup`；单个微服务自己的 JSON 字段、索引和运行数据校验仍留在所属微服务。测试可以调用正式检查入口，但不得复制检查规则。

## 依赖方向

```text
tools -> data
tools -> game（只复用纯战斗模拟或数据模型）
game -X-> tools
```

游戏进程不得导入本目录模块，不得读取 `tools/战斗校验/`，也不得在启动、抽取、战斗、结算或展示过程中计算评分和方向平衡。

## 战斗校验

旧方向评分模型与现行全局实体库不兼容，其脚本和配置已删除。新平衡体系建立前，`tools/` 不提供任何可能被误认为现行规则的评分结果。当前内容结构和跨域关系由 `全量JSON审查.py` 守卫，战斗语义同时通过战斗核心初始化和实际模拟验证。

只读审查和评分工具不得写回正式 JSON、玩家数据库或游戏实例。名称明确的生成脚本只能由维护者手动运行，并且只能把结果写入其声明的正式 JSON；游戏进程不得导入或自动调用。评分结果只能帮助维护者调整正式规则数值，不能成为游戏实体字段、玩家展示数据、随机权重、价格、存档或战斗公式。

`生成阵法数据.py` 维护首批经典阵名、五品固定数值和圣品最低投入，输出 `data/内容/阵法/阵法.json`。生成后必须使用项目的 Prettier 默认配置格式化正式 JSON。

`生成道侣结交内容.py` 根据每名道侣的身份、所在地和喜爱灵植重建性格方向、日常话语、赠礼话语与圆满回礼，输出世界目录中的正式道侣 JSON。它不会创建运行状态，也不会被游戏进程调用。

游戏仍可在读取实际所需文件失败、引用的实体不存在或玩家输入不满足玩法前置条件时拒绝执行；这是运行失败处理，不是全库校核。完整内容是否可发布，只由本目录工具判断。

`战斗校验/校验全池权重.py` 只读检查功法、真意和气机的实体权重、名称关系及全局唯一性，同时确认城镇道侣不再携带随机遭遇权重。

`全量JSON审查.py` 只读扫描全部正式 JSON，不在首个错误处停止。它同时初始化 JSON、资源池和战斗核心，并检查编号、字段契约、角色主体、物品效果、炼药、炼器、修行内容、战场环境、阵法、世界分区、地点、掉落和道路闭包。

`重建全境地理.py` 是全境地理的唯一生成工具。它从同一份山河规划生成 11 个不规则区域、85 片地形、81 个地点坐标、100×100 地势和按坡度寻路的道路；区域与地形都输出逐行坐标带，地点海拔保持精确锚定。脚本只由维护者手动运行，游戏进程不得导入。

`战斗校验/验收战斗核心与战报.py` 只通过战斗公共接口建立一场包含功法、真意、气机、器律、战场环境、双方阵法与自动恢复丹的战斗，核对真实结算、事件分类、参战者统计、阵法归属、展示筛选和时间线终态。
