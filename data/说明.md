# 数据目录

`data` 只保存三类数据，边界固定：

```text
rules/   人物、修炼和战斗规则
content/ 世界、机制、物品、角色和敌人内容
*.db     正式资产或短期运行日志
```

## 规则

- `rules/人物/人物.json`：人物、本命武器、伙伴装配上限、经验与出生资产。
- `rules/修炼/修炼.json`：闭关和探险的时间、轮次与消耗。
- `rules/品级/品级-通用.json`：黄、玄、地、天、圣五档通用品级的阶序、抽取权重、能力倍率和价格系数。
- `rules/战斗/属性.json`：战斗属性、默认值、数值边界和必需属性。
- `rules/战斗/资源.json`：资源与上限属性的关系。
- `rules/战斗/流程.json`：伤害规则、行动规则和战斗事件。
- `rules/战斗/原子能力.json`：能力类别、执行器、字段 Schema、嵌套和约束。
- `rules/战斗/战报.json`：战报协议、配色、事件分类、格式字段和前端界面词典。

## 内容

- `content/世界/*.json`：世界、坐标、地点功能及角色/敌人资源文件引用。
- `content/物品/功法/功法-*.json`：按类型拆分的功法、随机词条池和完整能力组成。
- `content/战斗机制/*.json`：可被双方复用的机制能力树与基础词条。
- `content/物品/附魔技能书/物品-附魔-*.json`：按主方向归档的附魔物品及完整能力组成。
- `content/物品/宝石/物品-宝石-*.json`：按主方向归档的宝石物品及完整能力组成。
- `content/角色方向/方向-*.json`：方向的资质范围及功法、附魔、宝石文件池。
- `content/物品/类别/物品-类别.json`：纳戒分类及展示顺序。
- `content/物品/<类别>/物品-<类别>-<用途或来源>.json`：实际物品、使用效果、评分和参考价。
- `content/角色/伙伴修士/伙伴修士-<地点>.json`：提供修士功能地点中的可交谈修士和后续伙伴候选。
- `content/敌人/修士/敌对修士-<流派>.json`：按战斗流派划分的敌对修士资源。
- `content/敌人/灵兽/灵兽-*.json`：按活动范围、种类和实力层级拆分的灵兽资源池。

角色、敌人、功法、附魔和宝石目录不使用对象清单文件；物品目录只保留一份分类顺序声明。加载器递归读取
目录内全部 `.json`，抹平目录层级后按文件名稳定展开；整个
`data` 树中的 JSON 文件名全局不能重复，同一分类中的对象名也不能重复，任何资源池文件不能是空文件。
世界配置中的 `修士池`、`敌人池` 填写一个或多个 JSON
文件名，不枚举文件内部对象。地点组件按填写顺序把这些文件中的对象整合并去重；遭遇触发时直接从
整合后的对象池按对象 `权重` 抽取，不先抽文件，因此文件拆分方式不会产生第二层随机权重。

地点不配置安全或危险字段，只声明 `可用功能`。启用“修士”必须配置伙伴修士池，启用“探险”必须配置
灵兽池；敌对修士不进入普通地点或探险池，由后续秘境等独立玩法按需引用。伙伴候选由角色的
`方向池` 填写 `方向-*.json` 文件名；方向文件中的三类池继续填写完整的功法、附魔、宝石 JSON 文件名，
不逐个枚举对象。加载器展开文件后再校验候选数量。伙伴三类装配上限直接写在
人物规则中，当前均为 3；展开后的方向池少于对应上限或引用不存在会阻止启动，不回退到全内容池。

附魔与宝石文件本身就是可进入纳戒的底座，同时保存完整能力树。加载器按名称生成附魔玉简或宝石的
运行期物品视图，权重和评分只维护一份。

`权重` 统一使用正整数，并按对象的综合能力价值配置。伤害、生存、辅助效果或泛用性越好，权重越高；抽中率与
`1 / 权重` 成正比，但权重不直接修改战斗数值。角色、敌人、物品、功法、品级、随机词条、附魔和宝石
遵守同一抽取语义。敌人通过 `掉落.物品池` 引用细分类物品 JSON，每次胜利固定按物品权重抽取一个，
引用处不再重复填写概率或数量。

品级是与权重分离的第二条轴。功法、附魔和宝石的品级能力倍率作用于整棵能力树，包括固定属性、伤害、
恢复、护盾、资源和状态辅助效果。普通物品按品级分别堆叠；丹药恢复量和评分乘能力倍率，参考价乘价格
系数。品级阶序按黄、玄、地、天、圣递增，用于“至少某品级”等范围判断。

## 不放进 JSON 的字典

代码中仍会出现运行字典，但它们不是配置：

- 执行器编号到 Python 函数的注册表，代表核心真正能执行的最小语义。
- 数据库行、战斗事件和接口响应组装出的结构化对象。
- 地点坐标索引、物品计数、冷却和状态快照等运行期数据。
- 通用 Schema 校验器的 DSL 语法；它只认识字段类型和引用类型，不认识具体功法或能力名。

这些对象会随一次请求或一次战斗生成，不能靠修改 JSON 定义执行代码。可编辑的固定内容不得重新写回
Python 模块级字典；需要新增时应先判断属于 `rules` 还是 `content`。
