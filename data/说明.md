# 数据目录

`data` 只保存三类数据，边界固定：

```text
rules/   人物、修炼和战斗规则
content/ 世界、功法、机制、物品、角色和敌人内容
*.db     正式资产或短期运行日志
```

## 规则

- `rules/人物/人物.json`：人物、本命武器、经验与出生资产。
- `rules/修炼/修炼.json`：闭关和探险的时间、轮次与消耗。
- `rules/战斗/属性.json`：战斗属性、默认值、数值边界和必需属性。
- `rules/战斗/资源.json`：资源与上限属性的关系。
- `rules/战斗/流程.json`：伤害规则、行动规则和战斗事件。
- `rules/战斗/原子能力.json`：能力类别、执行器、字段 Schema、嵌套和约束。
- `rules/战斗/战报.json`：战报协议、配色、事件分类、格式字段和前端界面词典。

## 内容

- `content/世界/*.json`：世界、坐标、地点功能及角色/敌人资源文件引用。
- `content/功法/*.json`：按类型拆分的功法、品级、随机词条池和完整能力组成。
- `content/战斗机制/*.json`：可被双方复用的机制能力树与基础词条。
- `content/物品/*.json`：纳戒物品、分类、使用效果、评分和参考价。
- `content/角色/*.json`：按地点或用途拆分的可交互修士资源池。
- `content/敌人/*.json`：按活动范围、种类和实力层级拆分的敌人资源池。

分类目录不使用清单文件。加载器直接读取目录内全部 `.json`，按文件名稳定展开；同一分类中的对象名
不能重复，任何资源池文件也不能是空文件。世界配置中的 `修士池`、`敌人池` 填写一个或多个 JSON
文件名，不枚举文件内部对象。地点组件按填写顺序把这些文件中的对象整合并去重；遭遇触发时直接从
整合后的对象池按对象 `权重` 抽取，不先抽文件，因此文件拆分方式不会产生第二层随机权重。

`权重` 统一使用正整数，数值越高越稀有，抽中率与 `1 / 权重` 成正比。角色、敌人、物品、功法品级
和随机词条遵守同一语义。敌人掉落条目里的 `概率` 是独立掉落判定，不替代对象池权重。

## 不放进 JSON 的字典

代码中仍会出现运行字典，但它们不是配置：

- 执行器编号到 Python 函数的注册表，代表核心真正能执行的最小语义。
- 数据库行、战斗事件和接口响应组装出的结构化对象。
- 地点坐标索引、物品计数、冷却和状态快照等运行期数据。
- 通用 Schema 校验器的 DSL 语法；它只认识字段类型和引用类型，不认识具体功法或能力名。

这些对象会随一次请求或一次战斗生成，不能靠修改 JSON 定义执行代码。可编辑的固定内容不得重新写回
Python 模块级字典；需要新增时应先判断属于 `rules` 还是 `content`。
