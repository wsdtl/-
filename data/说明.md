# data 数据关系总览

`data` 是游戏定义、规则、内容和展示契约的唯一正式来源。Python 只读取、索引和执行这些 JSON；校核、评分、平衡和生成脚本属于 `tools`，不得成为运行时规则来源。

总编排和数值口径见 [数据编排与数值口径.md](数据编排与数值口径.md)。旧项目只提供宏观物价与成长尺度，迁移结果见 `tools/数值对齐报告.md`；正式运行值已经落入当前 JSON，旧项目不作为运行时数据来源。

## 目录职责

| 部分 | 回答的问题 | 详细说明 |
| --- | --- | --- |
| `定义` | 有哪些编号、品级、属性、资源、事件、行程指标和原子能力 | [定义/说明.md](定义/说明.md) |
| `规则` | 初始化、成长、修行、行程和战斗怎样计算 | [规则/说明.md](规则/说明.md) |
| `内容` | 世界中实际有哪些地点、道路、角色、物品和机制 | [内容/说明.md](内容/说明.md) |
| `展示` | 游戏事实怎样转成战报、行程文字和界面数据 | [展示/说明.md](展示/说明.md) |

`database/game.db`、`database/runtime_log.db`、`.runtime/backups` 和 `.runtime/runtime_log_media` 是运行期数据，不属于 `data`。`data` 根目录只保留正式 JSON 及其说明文档。运行期数据库只能保存实体编号、实例状态和必要结果，不能复制 JSON 规则正文。

## 四种引用

| 引用目标 | JSON 中保存什么 | 示例 |
| --- | --- | --- |
| 具体编号实体 | 六位编号字符串 | `"400001"`、`"600001"` |
| 品级 | 两位品级编号 | `"01"` |
| 资源池 | 内容文件名，不带 `.json` | `"灵植-溪谷"` |
| 定义或规则注册项 | 注册名 | `"攻击"`、`"血气"`、`"造成伤害后"` |

资源池引用不能改成路径，也不能在引用处复制完整实体。只保存引用的池直接使用字符串列表：具体实体写六位编号，源池写不带 `.json` 的文件名。`内容` 下所有 JSON 文件名必须全局唯一，因为加载器会抹平目录层级并按文件名寻找资源池。

## 加载与执行顺序

```text
JsonDataReader 固定读取 定义/读取规则.json
-> 按规则扫描四个目录，每份 JSON 必须唯一匹配一个数据集和结构
-> GameDataLoader 根据规则建立 文件名到池、身份到实体 的不可变索引
-> 递归展开资源池
-> 校验编号前缀、池引用和循环引用
-> 各业务服务按数据集取得文件并校验自身业务约束
-> BattleEngine 执行战斗定义、规则和二次对象
-> BattleReportCatalog 按战斗展示 JSON 生成战报

世界核心读取地图、地势、道路和行程规则
-> 生成结构化行程事实
-> 按展示/行路/行程.json 生成玩家行程文字
-> 位置核心原子更新唯一玩家位置并立即抵达
```

`JsonDataReader` 会拒绝重复 JSON 键、重复内容文件名、未匹配规则和同时匹配多条规则的正式文件。`结构` 只描述对象、字典列表、编号实体列表、编号实体池、命名实体池、命名实体、编号池和源池等通用结构；功法、世界、角色等含义由取得相应数据集的服务解释。文件名已经表达的类别不能再在根节点外包一层同名键。

## 当前遗留关系

- 道侣 `圆满回礼`、赠礼累计、当前好感、首次圆满和首次邀约均由道侣结交服务解释并持久化。
- 敌方修士与灵兽的六阶段功法、真意、气机定向池，以及264名道侣的个人功法、真意、气机池已经建立；玩家全池由实体索引虚拟生成，不再维护全池 JSON。
- 尚未上线的玩法不能根据旧代码反推业务；已经上线的闭关与探险只能以当前 JSON、核心契约和持久化事实为准。

## 修改检查顺序

1. 先判断改动属于定义、规则、内容还是展示。
2. 新增、移动或改名文件时先检查 `定义/读取规则.json`，保证只命中一个数据集。
3. 修改定义时检查所有按名称引用它的规则、机制和内容。
4. 修改编号实体时保持编号不变；改名只影响展示，不得修改引用主键。
5. 修改池文件名时全库更新池引用，并保证新文件名仍全局唯一。
6. 修改战斗原子能力时同步检查机制、功法、真意、战斗规则和战报表达。
7. 修改 JSON 后先运行 Prettier、全量 JSON 初始化和编译；对应领域重建新测试后再运行该领域测试。平衡审查只在 `tools` 中运行。
