# 数据目录

`data` 只保存三类数据，边界固定：

```text
rules/   可调规则、协议和展示词典
content/ 世界、功法、敌人和物品内容
*.db     正式资产或短期运行日志
```

## 规则

- `rules/人物.json`：人物、本命武器、经验与出生资产。
- `rules/修炼.json`：闭关和探险的时间、轮次与消耗。
- `rules/属性.json`：战斗属性、默认值、数值边界和必需属性。
- `rules/资源.json`：资源与上限属性的关系。
- `rules/战斗流程.json`：伤害规则、行动规则和战斗事件。
- `rules/原子能力.json`：能力类别、执行器、字段 Schema、嵌套和约束。
- `rules/战报.json`：战报协议、配色、事件分类、事件名称、格式字段和前端界面词典。

## 内容

- `content/世界.json`：单世界、坐标、地点功能和敌人池。
- `content/功法.json`：功法、品级、随机词条池和完整能力组成。
- `content/机制.json`：可被双方功法复用的能力树。
- `content/词条.json`：随机词条及其属性范围。
- `content/敌人.json`：敌对修士的人物、本命武器、功法、战斗策略和掉落。
- `content/物品.json`：纳戒物品、分类、使用效果、评分和参考价。

## 不放进 JSON 的字典

代码中仍会出现运行字典，但它们不是配置：

- 执行器编号到 Python 函数的注册表，代表核心真正能执行的最小语义。
- 数据库行、战斗事件和接口响应组装出的结构化对象。
- 地点坐标索引、物品计数、冷却和状态快照等运行期数据。
- 通用 Schema 校验器的 DSL 语法；它只认识字段类型和引用类型，不认识具体功法或能力名。

这些对象会随一次请求或一次战斗生成，不能靠修改 JSON 定义执行代码。可编辑的固定内容不得重新写回
Python 模块级字典；需要新增时应先判断属于 `rules` 还是 `content`。
