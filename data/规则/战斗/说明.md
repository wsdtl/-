# 战斗规则关系说明

本目录负责战斗定义落地后的全局结算规则。战斗规则不保存具体技能和具体参战者。

## 文件关系

| 文件 | 作用 | 主要引用 |
| --- | --- | --- |
| `行动.json` | 行动条、冷却推进、恢复时点和运行硬上限 | 速度、血气恢复、精神恢复、战斗核心 |
| `伤害.json` | 命中、暴击、格挡、防御和伤害边界 | 战斗属性、造成伤害能力 |
| `状态反应.json` | 多个状态相遇时自动生成的反应 | 状态能力、原子能力 Schema |

## 行动关系

`行动.json` 的速度参数读取 `定义/战斗/属性.json -> 速度`。技能冷却单位固定为自身行动，并在行动开始、技能选择前推进；它不使用真实秒数，也不存在蓄势回合。

`行动.json -> 最高行动效率` 是所有参战者共用的行动公式边界。角色初始化只提供最终速度，战斗核心不读取角色类型、等级阶梯或构筑位。当前上限放开到 4，使超过标准速度的成长能够继续转化为行动效率。

行动开始恢复把资源映射到属性：

```text
血气 <- 血气恢复
精神 <- 精神恢复
```

事件链、能力链、触发技能、召唤物和构造物上限是防止组合机制无限递归或无限创建对象的运行硬边界。

## 伤害关系

`伤害.json` 与属性定义共同组成伤害流水线：

```text
命中率与闪避率
-> 暴击率、抗暴率与暴击伤害
-> 比例穿透、固定穿透与防御
-> 伤害加成与伤害减免
-> 格挡率、破格率与格挡减伤
-> 护盾和血气
```

具体能力可以声明无视防御、真实伤害、不可暴击或不可格挡，但全局上下限仍由规则和 Schema 共同约束。

## 状态反应

当前 `状态反应.json` 是空数组，表示核心不自动把任意两个状态合成为第三种结果。以后新增反应时，每项能力树仍必须符合 `定义/战斗/原子能力.json`。

## 修改检查

- 修改速度、命中或伤害边界时同步检查相关属性上下限。
- 提高运行硬上限前评估事件爆炸、战报大小和死循环风险。
