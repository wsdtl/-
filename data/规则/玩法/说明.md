# 玩法规则关系说明

本目录保存具体玩法的流程参数。闭关属于修行，探险属于外出玩法，因此二者统一归入“玩法”，不再把探险放在“修行”目录下。

## `闭关.json`

提供持续时间、轮次、经验、感悟功法概率和圆满状态清理开关。

```text
地点.可用功能 包含“闭关”
-> 闭关.json 计算完成轮次
-> 角色/修士修炼.json.经验 处理人物经验
-> 单独配置的功法池提供感悟候选
```

当前没有人物功法候选池，不能直接把全局 600 门功法当作闭关池。

## `探险.json`

提供持续时间、轮次、最大轮数、战斗行动上限、自动用药阈值和同场敌人抽取规则。每场具体人数由地点自己的 `单次遭遇敌人数` 决定，不在全局规则里抹平地点差异。

```text
地点.可用功能 包含“探险”
-> 展开地点.敌人池
-> 在地点.单次遭遇敌人数范围内确定本场人数
-> 按权重抽取敌人，同场优先不重复，候选不足才允许重复
-> 生成通用参战快照
-> BattleEngine 执行战斗
-> 按敌人掉落与交锋所得结算
```

## 当前状态

闭关和探险规则都能被统一JSON读取服务读取，但对应旧业务服务已经删除。以后每个玩法服务从统一JSON读取服务取得自己的规则，不得直接读取文件或保存代码默认值。

## 修改检查

- 时间与轮次必须能形成明确结算边界。
- 修改行动上限时评估战斗终局和战报体积。
- 所有提供探险的地点都必须保存合法的 `单次遭遇敌人数`，最小值不得大于最大值。
- 敌人候选少于最大遭遇人数时，只有在无重复候选已经耗尽后才能重复抽取。
- 探险掉落来自世界敌人内容，不在本目录重复配置。
- 玩法状态属于数据库实例，不能写入规则 JSON。
