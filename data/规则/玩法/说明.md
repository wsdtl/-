# 玩法规则关系说明

本目录保存具体玩法的流程参数。闭关属于修行，探险属于外出玩法，因此二者统一归入“玩法”，不再把探险放在“修行”目录下。

## `同行.json`

统一定义道侣进入具体玩法环节时的三种身份：`随行`只同步位置，`相助`建立协作快照但不进入正式名单，`并肩`建立完整参与快照并进入正式名单。具体玩法必须按环节主动声明；没有 `同行道侣` 字段时不得读取同行道侣，也不得给予隐式加成。

`可无`表示没有同行道侣时玩法仍可独自进行，`必须`表示缺少同行道侣时不能开始。同行身份只决定是否纳入玩法，具体伤势、消耗、成长和物资归属仍由所属玩法规则定义。

## `行路.json`

行路把同行道侣声明为`随行`：玩家移动后，道侣位置继续来源于所属玩家，但不建立行动快照、不获得行路结算。队伍与宗门成员跟随领路人的位置规则由 `规则/位置/同行.json` 负责，不在本文件重复定义。

## `闭关.json`

提供持续时间、轮次、经验、感悟功法概率和圆满状态清理开关。

```text
地点.可用功能 包含“闭关”
-> 闭关.json 计算完成轮次
-> 角色/成长/修士修炼.json.经验 处理人物经验
-> 单独配置的功法池提供感悟候选
```

当前没有人物功法候选池，不能直接把全局 600 门功法当作闭关池。

## `探险.json`

提供持续时间、场次、战斗行动上限、自动用药阈值、跨场资源连续性、敌人抽取、掉落均分和按时解封规则。当前一次探险最多持续 30 分钟，每场代表 120 秒，最多 15 场；我方正式单位全部战败时提前结束。每场敌人数由“开始时我方正式单位数 × 地点自己的 `单次遭遇敌人倍率`”确定，中途死亡不减少后续场次的敌人数基数。

```text
地点.可用功能 包含“探险”
-> 根据探险功能展开同目录 `<地点>敌人.json`
-> 在地点.单次遭遇敌人倍率范围内确定本场倍率
-> 乘以开始时我方正式单位数，确定本场敌人数
-> 按权重抽取敌人，同场优先不重复，候选不足才允许重复
-> 同行道侣在战斗环节以“并肩”身份进入正式参战名单
-> 在开始时生成全部敌人、战斗和奖励快照
-> BattleEngine 顺序执行最多 15 场真实战斗
-> 跨场只保留血气、精神、存活状态和每名用户自己的剩余丹药
-> 每名战败敌人只抽取一次自身掉落
-> 本场仍有角色存活的用户各取一份，整数数量向下取整，余数丢弃
-> 每 120 秒只解封累计进度，实际结束时间之后才能一次结算
```

探险只增加每名正式参战角色自己的本命武器经验，不增加人物或道侣经验。掉落只来自敌人自身的灵石、灵兽同名兽宝池和显式额外物品池，不取得当前地形的灵植或灵矿。奖励和最终血气、精神只在结束结算时写入；开始时确定的丹药消耗与完整结果必须和探险会话一同可靠保存。

## `铜雀台.json`

铜雀台只允许选择一名正在同行且至少二级的道侣。可抽取修为等于该道侣从一级升至当前等级已经消耗的全部修士经验，再加当前等级已有经验；资质、永久属性、三类构筑、本命武器和器律均不属于修为。

服用守真定契丹时，修为按 `100%` 转入人物经验，道侣好感与同行关系保持；不服丹时只转入 `70%`，好感归零、关系变为离契并返回原始地点。两种结算都会把道侣重置为一级零经验，但保留其资质、最高等级上限、突破记录、永久属性、构筑和本命武器。

人物只能接收到当前突破上限以内的经验，溢出部分直接丢弃。玩法服务必须在扣丹和写库前返回完整预览；正式结算由后续持久化事务一次完成，不能先改道侣再尝试增加人物经验。

## 当前状态

闭关、探险、铜雀台、同行、队伍和行路规则都能被统一 JSON 读取服务读取。探险、队伍和即时行路已经建立玩法服务：队长带领有序玩家同行，道侣由所属玩家自动进入探险正式单位；闭关、铜雀台与宗门同行尚未实现。后续玩法仍必须从统一 JSON 读取服务取得自己的规则，不得直接读取文件、保存代码默认值或用实现反向补齐主体规则。

## 修改检查

- 时间与轮次必须能形成明确结算边界。
- 修改行动上限时评估战斗终局和战报体积。
- 所有提供探险的地点都必须保存合法的 `单次遭遇敌人倍率`，最小值不得大于最大值。
- 敌人候选少于最大遭遇人数时，只有在无重复候选已经耗尽后才能重复抽取。
- 探险掉落来自世界敌人内容，不在本目录重复配置。
- 灵植和灵矿属于采集玩法，不进入普通探险掉落。
- 具体玩法只有声明 `同行道侣` 后才能取得当前同行实例；炼丹、炼器、突破等未声明玩法不得读取道侣。
- 一个玩法包含多个环节时必须逐环节声明同行方式，不能用一个总开关覆盖战斗、采掘和炼制。
- 玩法状态属于数据库实例，不能写入规则 JSON。
