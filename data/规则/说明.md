# 规则 JSON 关系说明

`规则` 保存跨实体复用的计算方式和流程参数。规则不枚举具体人物、地点、功法或物品。

## 分区

| 目录或文件 | 负责内容 | 详细说明 |
| --- | --- | --- |
| `角色/人物.json` | 新人物的规则引用与完整初始数据 | [角色/说明.md](角色/说明.md) |
| `角色/修士修炼.json` | 玩家、道侣、敌方修士共用的等级成长 | [角色/说明.md](角色/说明.md) |
| `角色/灵兽修炼.json` | 灵兽共用的较弱修炼成长 | [角色/说明.md](角色/说明.md) |
| `角色/道侣.json` | 道侣构筑位、好感、赠礼和资质成长修正 | [角色/说明.md](角色/说明.md) |
| `角色/灵兽.json` | 灵兽共用的角色规则 | [角色/说明.md](角色/说明.md) |
| `角色/敌方修士.json` | 当前敌方修士各档完整规则 | [角色/说明.md](角色/说明.md) |
| `构筑/*.json` | 构筑生成时的机制相冲与终止边界 | [构筑/说明.md](构筑/说明.md) |
| `玩法/闭关.json` | 闭关时长、轮次和收益参数 | [玩法/说明.md](玩法/说明.md) |

| `行路/行程.json` | 自动选路、道路剖面和路程折算 | [行路/说明.md](行路/说明.md) |

## 依赖方向

```text
定义 -> 规则 -> 内容实例/运行实例
```

规则可以引用定义中的属性、资源和机制编号，但不能反向定义新属性、新事件或新内容实体。内容可以选择使用哪条成长规则，但不能复制一份规则后偷偷分叉。

## 角色关系

道侣规则与世界道侣实体的关系是：

```text
世界道侣实体
  + 角色/道侣.json 的关系规则
  + 角色/道侣.json.构筑位
  + 角色/修士修炼.json
  + 定义/战斗/属性.json 默认值
  -> 未来持久化道侣实例
```

角色自身的 `构筑位` 只声明槽位数量，不提供功法、附魔和宝石候选池。角色候选池必须以后单独用池引用定义。

构筑生成规则与角色槽位相互独立：角色先给出需要生成多少项，`构筑/生成.json` 再引用 `构筑/相冲.json` 检查组合。战斗核心不参与这一步。
