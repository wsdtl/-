# 角色规则关系说明

本目录按完整角色主体或角色档次组织 JSON。文件名表达具体分类，一个文件中的每个字典保存该分类的一套完整规则；同一主体的属性、成长、修行槽位等相关字段不再机械拆成多个文件。

## 当前结构

```text
角色/
├─ 主体/
│  ├─ 人物.json
│  ├─ 道侣.json
│  ├─ 敌方修士.json
│  └─ 灵兽.json
├─ 成长/
│  ├─ 修士修炼.json
│  └─ 灵兽修炼.json
└─ 突破/
   └─ 境界突破.json
```

境界实体不属于角色规则目录，保存于 `内容/角色/境界.json`；它由 `规则/角色/突破/境界突破.json` 的目标境界引用，角色规则只负责解释等级成长。

## 人物初始化关系

```text
主体/人物.json.成长规则 --------> 成长/修士修炼.json
人物、道侣与敌方修士 ----> 规则/炼器/本命武器.json（由未来炼器服务提供独立武器状态）

未来玩家实例把当前等级、已累计的突破永久属性和本命武器状态交给角色服务。角色服务先执行修士成长，再累加永久属性，并按战斗属性定义的最低值与最高值收束；超出属性最高值的部分不进入战斗快照。角色服务不保存突破记录。

`主体/人物.json`、`主体/道侣.json` 和 `主体/敌方修士.json` 分别通过 `本命武器.器律池` 显式引用四个器阶池，这是对应主体的公共候选规则。世界道侣实体必须保存自己的本命武器名称、等级、经验和已占器律孔，不重复保存公共池名；角色与炼器服务不得根据人物等级或名称临时补造武器状态。敌方修士是按等级范围临时生成的战斗角色，其主体通过 `本命武器.等级来源: 实际等级` 明确武器等级；敌方修士实体中的本命武器 `攻击` 是一级基础攻击，后续攻击成长统一读取 `规则/炼器/本命武器.json`。灵兽没有本命武器，因此不定义器律池。

定义/战斗/属性.json 默认值
+ 人物.json.属性覆盖
-> 最终初始属性
-> 人物.json.资源 初始化当前资源
```

`人物.json.物品` 直接使用编号与数量字典列表，`人物.json.状态` 直接使用状态字典列表。文件名已经表达“人物”，JSON 内不再增加同名外层键或版本字段。

## 共享修炼成长

人物、道侣和敌方修士共用 `修士修炼.json` 中的等级、突破、属性成长和经验公式。灵兽使用 `灵兽修炼.json` 的属性基准、初始精神、等级、突破和经验公式；每个灵兽物种直接保存自己的完整 `每级成长`，不再用公共成长与差值拼装。

经验先按 `幂次基数 × 等级^等级幂次 + 等级基数 × 等级` 取整；40 级后再叠加后段的中段、高段和终段倍率。修士从 1 级升至 100 级累计需要 `351398872` 经验，灵兽同曲线成本为修士的 1.25 倍。未来角色服务必须作为唯一对外计算入口，其他业务不能自行复写公式。

道侣在修士成长结果上应用 `道侣.json.资质成长修正`。灵兽实体的 `每级成长` 必须直接给出血气上限、精神上限、攻击和防御四项最终值；角色业务不再读取隐藏的公共成长，也不执行差值加算。

```text
灵兽实际每级成长 = 敌人实体.每级成长
```

修士本体每级攻击为 `0.5`，本命武器每级攻击为 `1`；一级人物本体攻击 `5`、武器攻击 `10`，到一百级分别为 `54.5` 和 `109`，武器保持攻击主来源，本体成长也具有实际分量。

灵兽没有本命武器，肉身必须同时承担修士本体与武器两条成长线。当前 122 个灵兽物种直接保存以下完整每级成长：

- 血气上限 `14–22`，平均约 `18.46`；
- 精神上限固定为 `3`；
- 攻击 `1.2–2.1`，平均约 `1.54`，对应修士本体与武器合计的每级攻击 `1.5`；
- 防御 `1–1.9`，平均约 `1.38`。

灵兽用更强的血气、攻击和防御表达肉身路线，用较弱精神成长和较少修行槽位保持差异。不得再把灵兽解释成缺少武器的弱化修士，也不得为灵兽补本命武器、器律池或隐藏武器倍率。

## 修行槽位关系

修行槽位属于角色自身配置，不是战斗核心规则：人物读取 `人物.json.修行槽位`，道侣读取 `道侣.json.修行槽位`，敌方修士和灵兽都按实际等级读取对应阶梯中的 `修行槽位`。修行槽位只允许包含功法、真意和气机；器律孔属于本命武器，并由本命武器等级命中 `规则/炼器/器则.json.器阶` 后派生。敌方修士从 `2/2/2` 增长至 `12/12/12`，灵兽从 `1/1/1` 增长至 `6/6/6`。

功法、真意和气机候选池位于 `内容/功法`、`内容/真意` 和 `内容/气机` 的 `池` 子目录；角色规则或角色实体只保存池文件名引用，不复制候选内容。机制相冲和随机生成终止边界位于 `规则/构筑/`，不属于角色规则。

## 敌方修士档次

当前 `主体/敌方修士.json` 保存六档完整规则，每档通过 `功法池`、`真意池`、`气机池` 引用同阶段候选池。后续按敌人档次拆分时，应采用 `精英敌人.json`、`天灾敌人.json` 这类具体分类文件；每个文件仍保存该档敌人的完整字典或字典列表，不把等级、速度、抗控和修行槽位继续拆开。

群体攻击、阶段转换、受击反制、资源续航和绝境翻盘必须来自实际装配内容，不能写进角色成长 JSON。

## 灵兽档次

`主体/灵兽.json` 与 `主体/敌方修士.json` 使用相同的顶层和阶梯协议：`角色类型`、`成长规则`、`阶梯`，以及每阶的等级范围、修行槽位、三类候选池、每级速度、固定控制抵抗率和固定韧性。灵兽数值整体较低，但不是没有修炼与高阶成长。

敌人实体通过 `角色规则: 灵兽` 接入，生成实际等级后再命中对应阶梯；不得因敌人自身等级范围跨阶而提前写死候选池。灵兽没有本命武器，其肉身直接承担完整战斗成长，物种差异由属性覆盖、完整每级成长以及实际装配内容表达。

## 修改检查

- 先判断新数据属于哪个角色主体或敌人档次，再放入具体命名的 JSON。
- 同一主体内共同组成一条完整规则的字段保存在一起，不按字段名机械拆文件。
- 新角色规则必须使用敌方修士与灵兽共享的阶梯字段协议，不为新角色族另造初始化形状。
- 每个灵兽实体直接保存完整 `每级成长`；不得重新引入公共值加个体修正的二次拼装。
- 敌人 `交锋所得` 必须同时提供人物经验和本命武器经验范围，不能由玩法代码临时猜算。
- 根节点优先使用字典或字典列表；文件名已经表达的主体和类别不在 JSON 内重复。
- 只有可独立引用、可独立维护的完整分类才拆成新文件。
- 修改规则文件名时同步修改 JSON 引用和所有数据说明。
