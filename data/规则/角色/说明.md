# 角色规则关系说明

本目录按完整角色主体或角色档次组织 JSON。文件名表达具体分类，一个文件中的每个字典保存该分类的一套完整规则；同一主体的属性、成长、构筑位等相关字段不再机械拆成多个文件。

## 当前结构

```text
角色/
├─ 人物.json
├─ 修士.json
├─ 本命武器.json
├─ 道侣.json
├─ 灵兽.json
└─ 敌方修士.json
```

## 人物初始化关系

```text
人物.json.成长规则 --------> 修士.json
人物.json.本命武器规则 ----> 本命武器.json

定义/战斗/属性.json 默认值
+ 人物.json.属性覆盖
-> 最终初始属性
-> 人物.json.资源 初始化当前资源
```

`人物.json.物品` 直接使用编号与数量字典列表，`人物.json.状态` 直接使用状态字典列表。文件名已经表达“人物”，JSON 内不再增加同名外层键或版本字段。

## 共享修士成长

人物、道侣和敌方修士共用 `修士.json` 中的等级、突破、属性成长和经验公式。道侣在共享成长结果上应用 `道侣.json.资质成长修正`；敌方修士再按自身完整档次规则应用构筑位、速度成长和抗控成长。

## 构筑位关系

构筑位属于角色自身配置，不是跨角色规则：人物读取 `人物.json.构筑位`，道侣读取 `道侣.json.构筑位`，灵兽读取 `灵兽.json.构筑位`，敌方修士读取对应敌人档次中的 `构筑位`。灵兽六阶共用三功法、三附魔、三宝石上限，阶梯只改变候选范围。

功法、附魔和宝石候选池位于 `内容/物品` 的对应目录；角色规则或角色实体只保存池文件名引用，不复制候选内容。机制相冲和随机生成终止边界位于 `规则/构筑/`，不属于角色规则。

## 敌方修士档次

当前 `敌方修士.json` 保存六档完整规则，每档通过 `功法池`、`附魔池`、`宝石池` 引用同阶段候选池。后续按敌人档次拆分时，应采用 `精英敌人.json`、`天灾敌人.json` 这类具体分类文件；每个文件仍保存该档敌人的完整字典或字典列表，不把等级、速度、抗控和构筑位继续拆开。

群体攻击、阶段转换、受击反制、资源续航和绝境翻盘必须来自实际装配内容，不能写进角色成长 JSON。

## 灵兽档次

`灵兽.json` 使用与敌方修士相同的初窥、登堂、入微、圆融、镇域、天灾等级区间，但引用独立的灵兽功法、附魔和宝石池。敌人实体通过 `构筑规则: 灵兽` 接入，生成实际等级后再命中对应阶梯；不得因敌人自身等级范围跨阶而提前写死候选池。

## 修改检查

- 先判断新数据属于哪个角色主体或敌人档次，再放入具体命名的 JSON。
- 同一主体内共同组成一条完整规则的字段保存在一起，不按字段名机械拆文件。
- 根节点优先使用字典或字典列表；文件名已经表达的主体和类别不在 JSON 内重复。
- 只有可独立引用、可独立维护的完整分类才拆成新文件。
- 修改规则文件名时同步修改 JSON 引用和所有数据说明。
