# 定义 JSON 关系说明

`定义` 描述游戏数据可以使用哪些稳定身份和底层概念。它不保存某个具体人物、物品或技能，也不描述玩法流程。

## 文件关系

| 文件 | 定义什么 | 直接约束谁 |
| --- | --- | --- |
| `编号.json` | 六位实体编号、类别前缀、两位品级编号 | 道侣、普通物品、功法、附魔、宝石、机制 |
| `品级.json` | 品级编号、阶序、抽取权重、能力倍率、价格系数 | 物品实例及需要品级的能力实例 |
| `战斗/属性.json` | 37 项战斗属性及默认值、范围、单位 | 初始人物、成长、敌人、道侣、宝石、战斗计算 |
| `战斗/资源.json` | 血气、精神、护盾与各自上限属性 | 参战快照、恢复、消耗、伤害和战报 |
| `战斗/事件.json` | 57 个事件窗口、事实和可修改项 | 监听机制、事件改写、战报事件 |
| `战斗/原子能力.json` | 68 种能力节点的字段协议和执行器 | 机制、功法、附魔、状态反应 |
| `行路/行程指标.json` | 路线高度剖面和路程的稳定指标 | 世界道路、自动选路、行程展示 |

战斗定义的详细组合关系见 [战斗/说明.md](战斗/说明.md)。
行路定义的详细组合关系见 [行路/说明.md](行路/说明.md)。

## 编号关系

```text
编号前缀 + 四位流水号 = 六位稳定实体编号
品级编号 = 独立两位字符串
```

六位编号只表达实体身份，不表达品级、强度、地区或方向。资源池使用文件名，不使用编号；具体实体引用使用编号，不使用名称。

新增一种编号实体时必须同时检查：

1. `编号.json -> 编号前缀` 是否已有类别；
2. 内容文件中的 `类别` 是否与前缀一致；
3. `GameDataLoader` 是否把该文件识别为正确内容类别；
4. 数据库是否只保存编号而非展示名称。

## 品级关系

`品级.json` 自身不属于物品池。运行期先得到实体编号，再独立得到品级编号，最后形成实例：

```json
{
  "编号": "400001",
  "品级": "03"
}
```

`能力倍率` 只应作用于协议明确允许缩放的能力数值；`价格系数` 只用于价格。不得遍历所有数字进行无差别缩放。

## 修改边界

- 删除属性前，必须检查成长、初始覆盖、敌人、道侣、宝石、机制和展示摘要。
- 删除资源前，必须检查 `资源.json`、原子能力、行动恢复和战报资源配置。
- 删除事件前，必须检查全部监听机制与事件改写机制。
- 修改编号前缀会破坏存档身份，已有前缀和编号不得重排。
