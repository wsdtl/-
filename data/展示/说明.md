# 展示 JSON 关系说明

`展示` 只决定已经发生的游戏事实如何命名、分类、着色和组织，不参与战斗裁定。

## `战报.json` 的输入与输出

```text
BattleEngine 结构化结果
+ 定义/战斗/属性.json 的属性含义
+ 定义/战斗/资源.json 的资源含义
+ 定义/战斗/事件.json 的事件类型
+ 战斗机制和技能的展示名称
+ 展示/战报.json
-> 标准化战报
-> 战报展示协议
-> static/battle-report 页面
```

## 战报根部分

| 部分 | 作用 |
| --- | --- |
| `协议` | 战报 Schema 名称、展示协议和展示版本 |
| `游戏名称` | 战报对外显示的游戏名 |
| `视觉` | 前景色、系统色、参战者颜色和资源颜色 |
| `标准化` | 原始事件类型到分类、名称和明细格式的映射 |
| `展示` | 界面文案、色调、顺序、状态和结果表现 |

## 与战斗 JSON 的边界

- 事件是否触发由战斗核心和事件定义决定，展示不能创造事件。
- 属性和资源数值由战斗结算决定，展示只能选择格式。
- 改事件名称或资源名称时，必须同步检查战报映射。
- 战报颜色、标签和折叠策略不能影响伤害、目标、概率或胜负。

## `行程.json` 的输入与输出

```text
规则/行路/行程.json 选出的结构化行程事实
+ 经由地点与道路类别
+ 行程距离、最高海拔和累计爬升
+ 展示/行程.json
-> 起程、经由、地势、抵达和总览文字
```

道路措辞负责把官道、军道、荒径和栈道写成自然行程；方向措辞负责北上、南下和斜向行进；爬升与海拔措辞负责表现山势和环境。展示只描述已经选出的路线，不能改变路线权重，也不能用境界或海拔拒绝玩家到达目的地。

当前境界JSON尚未建立，因此 `行程.json` 不提前登记境界名称。未来境界提供赶路方式、速度和可选措辞后，再由展示层组合，不修改道路与目的地可达性。

## 公共服务关系

战报生成器位于战斗基础设施中，静态页面和控制台入口位于 `game/public` 与 `static`。它们读取展示结果，但不能成为第二份战斗规则。

## 修改检查

1. 修改协议名或版本时同步检查前端兼容性和演示战报。
2. 新增资源时补资源名称和颜色。
3. 新增事件类型时决定分类、显示名、明细格式和默认降级表现。
4. 修改界面字段后重新生成演示战报并打开静态页面验证。
5. 修改道路类别时同步补充行程道路措辞。
6. 修改行程模板时检查占位符都有对应结构化事实。
