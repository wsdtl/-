# 世界 JSON 关系说明

世界内容采用“世界 -> 区域 -> 地点 -> 地点资源池”的层级。目录用于就近维护，运行时身份仍由文件名或实体编号决定。

## 层级关系

```text
地图规则.json
  └─ 出生地 ------------------------------> 某个地点文件名

<区域>/<区域>.json
  └─ 坐标范围
      └─ <区域>/<地点>/<地点>.json
          ├─ 所属区域 --------------------> 区域文件名
          ├─ 天材地宝池 ------------------> 物品-天材地宝-*.json
          ├─ 道侣池 ----------------------> 同地或其他 *道侣.json
          └─ 敌人池 ----------------------> 同地或其他 *敌人.json
```

当前世界为三轴坐标，所有区域和地点都位于 `z=0`。区域范围必须包含其地点，地点三轴坐标必须全局唯一，出生地必须指向真实地点。

## 世界与区域文件

`地图规则.json` 定义世界名称、说明、出生地和总坐标边界。区域文件定义区域类别、坐标范围和说明。世界与区域不保存地点列表，地点通过自己的 `所属区域` 建立关系。

区域和地点的名称默认来自文件名，因此改名必须同时移动文件、修改目录和更新所有名称引用。

## 地点文件

地点文件负责：

- `所属区域` 和三轴 `坐标`；
- 展示用地点类型、地形和说明；
- `可用功能`；
- 天材地宝、道侣和敌人资源池引用。

功能与池必须保持一致：提供修士交互的地点才需要道侣池，提供探险的地点才需要敌人池。当前业务服务已删除，因此这些字段是未来玩法的输入，不代表对应命令已经可用。

## 道侣文件

道侣文件根节点是数组，每名道侣使用 `50` 前缀六位编号。道侣通过以下数据组合：

```text
道侣实体.角色类型/成长规则
+ 定义/战斗/属性.json 默认值
+ 道侣实体.属性覆盖与实力波动
+ 规则/成长/修士.json
+ 规则/道侣.json 的好感和资质修正
-> 未来道侣实例
```

道侣 `结交.喜爱天材地宝池` 引用天材地宝文件名。当前 `圆满回礼` 仍按物品名称和品级名称保存，这是尚未统一到实体编号与品级编号的遗留字段，重建结交业务前必须处理。

道侣目前不保存功法、附魔、宝石候选池。角色分池需要以后单独设计，不能从道侣称号或说明推断。

## 敌人文件

敌人文件根节点是“敌人名称 -> 定义”的对象，没有六位敌人编号。一次敌人实例由以下数据组合：

```text
敌人定义
-> 按权重从展开后的敌人池抽取
-> 在等级范围内确定等级
-> 属性默认值 + 属性覆盖 + 每级成长
-> 对实力波动列出的属性独立波动
-> 形成 CombatantSnapshot
```

修士敌人使用 `规则/成长/修士.json`；灵兽可以在自身定义中保存 `每级成长`。所有属性名都必须来自 `定义/战斗/属性.json`。

敌人 `掉落.物品池` 引用普通物品文件名，`交锋所得.本命武器经验` 关联 `规则/成长/本命武器.json`。掉落结算属于未来探险业务，不属于战斗核心。

## 池展开规则

地点可以引用多个池文件。运行时应先展开所有文件并合并候选，再按对象权重抽取，不能先抽文件再抽对象，否则文件拆分方式会改变概率。

```text
地点中的池文件名数组
-> 展开每个文件的对象
-> 合并候选
-> 按编号或名称决定是否去重
-> 对最终候选执行抽取
```

## 修改检查

- 新地点必须位于世界和所属区域边界内，并使用唯一坐标。
- 改地点名时检查出生地和所有名称引用。
- 改道侣编号时会破坏持久化身份，禁止修改已有编号。
- 改池文件名时检查地点、道侣喜好和敌人掉落。
- 世界数据能加载不代表业务已实现；不要在世界 JSON 中塞入流程状态。
