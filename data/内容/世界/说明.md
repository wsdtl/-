# 世界 JSON 关系说明

世界内容采用“世界 -> 区域 -> 地点 -> 地点资源池”的层级。目录用于就近维护，运行时身份由文件名或实体编号决定；区域归属由路径推导，不在地点 JSON 重复保存。当前共 81 个正式地点。

## 层级关系

```text
晓楠修仙界.json
  ├─ 出生地 ------------------------------> 某个地点文件名
  ├─ 道路 --------------------------------> 道路/*.json
  └─ 行程规则 ----------------------------> 规则/行路/行程.json

地势.json
  └─ 坐标边界 + 水平尺度 + 海拔范围 + 地表高度

<区域>/<区域>.json
  ├─ 坐标范围
  ├─ 地形分区 ----------------------------> 战场环境名称
  └─ <区域>/<地点>/<地点>.json
          ├─ 灵植池 ----------------------> 灵植-*.json
          ├─ 灵矿池 ----------------------> 灵矿-*.json
          ├─ 道侣池 ----------------------> 同地或其他 *道侣.json
          ├─ 敌人池 ----------------------> 同地或其他 *敌人.json
          └─ 单次遭遇敌人数 --------------> 规则/玩法/探险.json
```

当前世界只有一个界，不设置位面层或跨界坐标。`x`、`y` 像经纬度一样唯一定位全境 `0..99` 的100×100个地表位置；每格尺度和海拔都由 `地势.json` 定义。区域范围必须包含其地点，地点平面坐标必须全局唯一，出生地必须指向真实地点。

## 世界与区域文件

`晓楠修仙界.json` 只定义世界说明、出生地、道路和行程规则。唯一的 `地势.json` 自行定义坐标边界、水平尺度和海拔范围，不需要世界再次引用。区域文件定义区域类别、坐标范围、完整地形分区和说明；区域海拔范围由世界服务从地势表计算。世界与区域不保存地点列表，地点所属区域仍由 `内容/世界/<区域>/<地点>/` 的目录路径确定。

区域和地点的名称默认来自文件名，因此改名必须同时移动文件、修改目录和更新所有名称引用。

## 地点文件

地点文件负责：

- 二维 `坐标`；区域由目录路径确定，海拔从地势取得；
- 展示用地点类型和说明；地形由坐标所在的区域地形分区确定；
- `可用功能`；
- 灵植、灵矿、道侣和敌人资源池引用；
- 普通探险每场敌人数范围。

功能与池必须保持一致：提供修士交互的地点才需要道侣池，提供探险的地点必须同时具有敌人池和 `单次遭遇敌人数`。该范围表达一次普通探险战斗会生成多少名敌人；高危地点可以通过更高等级形成压力，不应一律依赖堆叠人数。世界微服务已经校验并返回这些功能定义；具体命令与玩法状态仍由未来业务服务实现。

地点只保存二维坐标。地点海拔始终由 `地势.json.地表高度[y][x]` 推导，不能在地点中重复保存第三个坐标或单独调整高度。

区域 `地形分区` 是全境唯一的地形事实源。每个区域坐标必须恰好命中一个分区，不允许重叠、缺口或默认兜底；登记地点与未登记坐标使用完全相同的解析方式。

## 地势文件

`地势.json` 覆盖 `x=0..99`、`y=0..99` 的全部整数坐标，共100行、每行100项。高度函数直接查表：

```text
H(x, y) = 地表高度[y][x]
```

分辨率为1，水平每格10000米，所有高度都是整数米。海平面为 `z=0`，当前地表从芦汀村芦苇湿地的-1049米延伸到无光崖的28710米；低于海平面的数值表示湖泽、河口、湿地等低地，不是地下层。南方湖泽与河口保持低地，镇岳防线整体抬升，烬脊群山和天裂禁地形成万米级高地。详细契约见 [地势说明.md](地势说明.md)。

## 道路文件

`道路` 目录按官道、乡道、山道、堤道、军道、荒径和栈道拆成七个文件，共114条道路，覆盖全部81个地点并保持全境连通。每条道路只保存起点、终点和连续的二维坐标；高度、坡度、爬升与距离全部从地势和地图尺度计算，不复制进道路。

```text
道路起点/终点地点名
+ 道路逐格坐标
+ 地势高度表
+ 水平每格10000米
-> 有方向的道路剖面
-> 比较所有候选路线
-> 取得最优行程并生成叙事
```

道路默认双向，但上山和下山必须分别计算。所有已登记地点始终可达；海拔和坡度只参与路线权重与行程描述，不构成人物准入条件。未来境界可以改变赶路方式、速度和措辞，但不能封锁目的地。详细契约见 [道路/说明.md](道路/说明.md)。

## 道侣文件

道侣文件根节点是数组，每名道侣使用 `50` 前缀六位编号。道侣通过以下数据组合：

```text
+ 规则/角色/主体/道侣.json.角色类型与成长规则
+ 定义/战斗/属性.json 默认值
+ 道侣实体.属性覆盖与实力波动
+ 规则/角色/成长/修士修炼.json
+ 规则/角色/主体/道侣.json 的好感和资质修正
-> 未来道侣实例
```

道侣 `结交.灵植池` 引用灵植文件名，`圆满回礼` 使用六位物品编号、两位品级编号和数量。结交业务只需按这些稳定引用取得定义，不能依赖展示名称。

每名道侣通过 `功法池`、`真意池` 和 `气机池` 显式引用 `内容/功法/池/道侣`、`内容/真意/池/道侣` 和 `内容/气机/池/道侣` 下自己的候选池文件。个人池从全池逐角色建立，不使用公共道侣池兜底。

道侣共同拥有本命武器，其四阶器律池统一由 `规则/角色/主体/道侣.json.本命武器.器律池` 定义。世界道侣实体不重复保存公共池名，只保留个人功法池、真意池、气机池和人物差异；未来某名道侣确有专属器律规则时，再为该实体设计明确的覆盖协议。

## 敌人文件

敌人文件根节点是“敌人名称 -> 定义”的对象，没有六位敌人编号。一次敌人实例由以下数据组合：

```text
敌人定义
-> 按权重从展开后的敌人池抽取
-> 抽取数量来自地点.单次遭遇敌人数
-> 在等级范围内确定等级
-> 通过角色规则按实际等级命中六阶规则
-> 取得对应功法池、真意池和气机池
-> 属性默认值 + 成长规则初始属性 + 实体属性覆盖
-> 修士读取共享成长，灵兽读取实体完整每级成长
-> 对实力波动列出的属性独立波动
-> 形成 CombatantSnapshot
```

所有敌人都显式保存 `角色规则`。修士敌人指向 `规则/角色/主体/敌方修士.json`，灵兽指向 `规则/角色/主体/灵兽.json`；两类规则使用同一套六阶字段协议，并按实际生成等级选择构筑位、候选池、速度成长、控制抵抗率和韧性。

敌方修士共同使用的四阶器律池由 `规则/角色/主体/敌方修士.json.本命武器.器律池` 定义；世界敌方修士实体的 `本命武器` 只保存该武器独有的名称和一级基础攻击。灵兽天生以肉身为战斗器体，不设本命武器、不写空器律池，也不为满足字段整齐而伪造器律；对应的攻击、血气和防御全部由灵兽实体自身更强的完整 `每级成长` 承担。

敌人的等级范围可以跨越阶梯边界，因此池不能直接写死在敌人定义中。敌方修士通过角色规则引用 `规则/角色/成长/修士修炼.json`；灵兽通过 `规则/角色/成长/灵兽修炼.json` 取得公共等级、突破和经验规则，并由物种实体的 `每级成长` 直接给出完整肉身成长值。灵兽每级血气为 `14–22`、攻击为 `1.2–2.1`、防御为 `1–1.9`，不再套用弱化修士尺度。所有属性名都必须来自 `定义/战斗/属性.json`。

普通探险的地域角色边界固定如下：南方六州只使用灵兽，北方朔风荒原、寒渊林海、烬脊群山和天裂禁地只使用敌对修士，镇岳防线同时存在敌对修士与灵兽。该边界描述的是地点敌人池的组成，不要求防线每一场战斗都固定生成两类角色。

敌对修士可以在名称中带所在地，表达其驻守、潜伏或活动身份。灵兽名称必须是可以脱离地点独立成立的物种名，不添加地点前缀；出没地点由所在敌人池表达，不能把池归属重复塞进物种名称。

敌人 `掉落.物品池` 引用所在地点的灵植池和灵矿池。灵兽额外按自身完整名称引用一个独有兽宝池，池内实体使用 `21` 前缀编号并按权重抽取；敌对修士不得引用兽宝池。`交锋所得.本命武器经验` 关联 `规则/炼器/本命武器.json.经验`。掉落结算属于未来探险业务，不属于战斗核心。

## 池展开规则

地点可以引用多个池文件。运行时应先展开所有文件并合并候选，再按对象权重抽取，不能先抽文件再抽对象，否则文件拆分方式会改变概率。

```text
地点中的池文件名数组
-> 展开每个文件的对象
-> 合并候选
-> 按编号或名称决定是否去重
-> 在地点范围内确定本场人数
-> 同场优先抽取不同敌人
-> 候选不足时才允许重复抽取
```

## 修改检查

- 新地点必须位于地势边界及其目录所属区域的边界内，并使用唯一坐标；地点不得重复保存地形。
- 新增或调整地形分区时必须完整覆盖区域且互不重叠，所用地形必须存在对应战场环境。
- 新地点只保存唯一 `(x, y)`；修改地势后只需同步区域高度范围并重新校验地点海拔。
- 新地点必须接入道路网络；修改道路时检查坐标连续、端点一致和出生地可达性。
- 改地点名时检查出生地和所有名称引用。
- 提供探险的地点必须配置两个整数构成的 `单次遭遇敌人数`，且均大于零。
- 修改敌人等级时必须核对其实际等级命中的六阶构筑池；南方聚居地、防线、北境和禁地不能继续共用同一低阶范围。
- 检查地域角色边界：南方六州不得出现修士敌人，北方四域不得出现灵兽，镇岳防线的总池必须同时包含两类。
- 灵兽名称必须全局唯一且不带所在地点前缀；移动出没池时不应被迫改物种名。
- 每名敌人的物品池必须包含所在地的灵植池和灵矿池；每种灵兽必须额外引用以自身完整名称命名的兽宝池，池内至少包含三项 `21` 前缀兽宝。
- 改道侣编号时会破坏持久化身份，禁止修改已有编号。
- 人物、道侣和敌方修士主体必须显式引用四阶器律池；世界实体不得机械复制主体公共池，灵兽不得出现本命武器或器律池。
- 改池文件名时检查地点、道侣喜好和敌人掉落。
- 世界数据能加载不代表业务已实现；不要在世界 JSON 中塞入流程状态。
