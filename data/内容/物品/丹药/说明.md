# 丹药 JSON 关系说明

丹药是可堆叠普通物品，使用 `10` 前缀编号。恢复丹与战丹分目录维护，共 166 个实体：恢复丹 6 个，战丹 160 个。

```text
丹药/
  恢复丹/  # 血气、精神
  战丹/    # 基础、单监听药性与复合机制药性
```

## 关系

```text
丹药实体.编号 <-------- 规则/角色/人物.json.物品[].编号
丹药实体       <-------- 敌人掉落或未来其他物品池
使用效果       --------> 未来物品使用业务
恢复量/恢复百分比 --------> 血气或精神资源
战丹.战前状态  --------> 下一场正式战斗的预置状态
战丹.战斗机制  --------> 内容/战斗机制/*.json 的稳定机制编号
战丹.强度/丹位 --------> 规则/炼药/战丹.json
参考价         --------> 定义/品级.json.价格系数
```

`使用效果.类型` 是普通物品业务语义，不等同于战斗原子能力；未来使用器必须显式适配该类型，不能把文字说明当规则解析。`寄存战丹` 只保存下一场战斗需要的状态定义和稳定机制编号，战斗装配业务把机制编号解析为状态监听，战斗核心不读取纳戒或丹方。

恢复丹统一使用相对资源上限的恢复百分比，当前血气三档为 `8% / 15% / 25%`，精神三档为 `6% / 12% / 20%`。若实例带品级，品级能力倍率怎样作用于恢复量必须由正式物品协议统一执行，不能在每种丹药上写不同代码。

每枚战丹都必须有一张丹方。不同丹方可以复用炉法，由强度、炼制难度、药引、炉法与辅材实际组合共同决定成丹，不再要求一枚战丹机械对应一种专用炉法。

## 修改检查

- `类别` 必须是丹药，编号必须使用 `10` 前缀。
- 恢复目标必须对应已登记资源。
- `寄存战丹` 必须声明 `战前状态`，且状态持续单位必须是 `整场战斗`；若声明 `战斗机制`，编号必须存在于战斗机制实体中。
- 改编号会破坏初始物品和未来存档引用，禁止重排。
- 新增使用效果类型时必须同步建立通用执行语义和测试。
