# 宝石 JSON 关系说明

宝石是固定属性装配对象，使用 `42` 前缀编号。当前 78 个属性家族池、703 颗宝石，覆盖 37 个单属性和 666 个无序双属性组合。

## 结构关系

```text
宝石实体.能力[0]
-> 固定属性加成
-> 属性名必须来自 定义/战斗/属性.json
-> 装配后合并到 CombatantSnapshot.attributes
```

宝石不引用战斗机制，不监听事件，不生成主动或被动技能。双属性宝石只是一个节点中的两个属性，不是两颗单属性宝石的运行时拼接。

## 与其他 JSON 的关系

- 各角色自身 JSON 中的 `构筑位` 决定角色宝石位；
- 宝石数量只由角色自身的构筑位决定；
- `定义/品级.json` 为宝石实例提供品级能力倍率；
- 玩家使用解析全部 `物品-宝石-*.json` 后按编号合并的全局宝石索引；
- 道侣实体通过 `个人宝石池` 引用 `道侣池宝石/` 下自己的24项编号候选；
- 敌方修士通过 `宝石池` 引用 `敌人池宝石/` 下对应阶段的源池候选。
- 灵兽通过 `规则/角色/灵兽.json` 引用 `灵兽池宝石/` 下对应阶段的源池候选。

宝石源文件保存完整实体字典列表。道侣个人池直接保存宝石编号字符串列表，敌人阶段池直接保存宝石源池文件名字符串列表；引用项不再套单键字典。

同一编号无论出现在哪个池或装配到谁身上，属性定义和权重都必须完全相同。文件分类和名称都不能改变实体实际属性。

## 修改检查

- 编号必须使用 `42` 前缀。
- 每颗宝石只能有一个 `固定属性加成` 根节点。
- 属性名、数值边界必须符合属性定义。
- 双属性组合不区分排列顺序，不能同时新增“攻击防御”和“防御攻击”。
- 宝石不保存评分、方向、兼容标签或随机词条；每颗宝石在实体根节点保存自身逆权重。
- 权重必须是正整数；同名宝石权重必须一致，不同名称的宝石不得与任何功法、附魔或其他宝石使用相同权重。
- 改宝石编号时同步检查道侣个人池；改源池文件名时同步检查敌人阶段池。
