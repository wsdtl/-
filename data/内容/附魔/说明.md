# 附魔 JSON 关系说明

附魔是本命武器上的被动战斗对象，使用 `41` 前缀编号。当前 20 个分类池、600 个附魔。

## 结构关系

```text
附魔实体
-> 一个被动技能
-> 一个引用被动机制节点
-> 内容/战斗机制中的监听机制
```

附魔没有主动技能，不形成完整功法循环。被动技能与监听节点必须符合 `定义/战斗/原子能力.json`，所监听事件必须存在于 `定义/战斗/事件.json`。

## 与其他 JSON 的关系

- 各角色自身 JSON 中的 `构筑位` 决定角色附魔位；
- `规则/构筑/相冲.json` 保存附魔参与的机制相冲；
- `定义/品级.json` 为附魔实例提供独立品级；
- 玩家从解析全部附魔实体文件后按编号合并的虚拟全池随机，不维护全池 JSON；
- 道侣不使用公共定向总池；每个角色从 `池/道侣/` 的个人附魔池随机；
- 敌人通过 `池/敌方修士/` 的六个阶段源池取得杀伐、压制和控制候选池；
- 灵兽通过 `池/灵兽/` 的六个阶段源池取得追击、状态、御灵和绝境候选池。

附魔不保存评分、方向、兼容标签或随机词条。每个附魔在实体根节点保存自身逆权重；定向池不复制附魔实体：道侣个人池直接保存附魔编号字符串，敌人阶段池直接保存源池文件名字符串。六个敌人阶段池彼此独立，不隐式继承前一阶段。

## 修改检查

- 编号必须使用 `41` 前缀。
- 权重必须是正整数；同名实体权重必须一致，异名实体权重不得重复。
- 根能力必须是被动技能，机制引用必须指向有效被动监听机制。
- 修改监听机制会影响所有引用该机制的附魔和功法。
- 新增附魔不能靠改名复制已有实际能力。
- 新增、删除或改名源池时同步更新敌人阶段池；改附魔编号时同步检查道侣个人池。
