# 内容 JSON 关系说明

`内容` 保存世界中真实存在、可以被引用或抽取的对象。内容文件不重新定义编号规则、属性语义或战斗公式。

## 三个内容域

| 目录 | 当前内容 | 详细说明 |
| --- | --- | --- |
| `世界` | 1 个世界、11 个区域、80 个地点、113 条道路、264 名道侣、160 个敌人 | [世界/说明.md](世界/说明.md) |
| `战斗机制` | 80 个机制池文件、1600 个编号机制 | [战斗机制/说明.md](战斗机制/说明.md) |
| `物品` | 普通物品、功法、附魔技能书、宝石 | [物品/说明.md](物品/说明.md) |

## 文件身份就是分类入口

加载器按文件名和位置判定内容类别：

| 文件形式 | 加载类别 | 单项身份 |
| --- | --- | --- |
| `地图规则.json` | 世界 | 文件自身 |
| `地势.json` | 全境地表高度 | `(x, y)` 整数坐标 |
| `世界/道路/*.json` | 全境道路 | 起点与终点地点名 |
| `世界/<区域>/<区域>.json` | 区域 | 文件名 |
| `世界/<区域>/<地点>/<地点>.json` | 地点 | 文件名 |
| `*道侣.json` | 道侣 | 六位编号 |
| `*敌人.json` | 敌人 | 对象键名称 |
| `功法-*.json` | 功法 | 六位编号 |
| `物品-附魔-*.json` | 附魔 | 六位编号 |
| `*敌人功法池.json` | 功法源池引用 | 源池文件名 |
| `*灵兽功法池.json` | 灵兽功法源池引用 | 源池文件名 |
| `<道侣编号>-<名称>功法池.json` | 道侣个人功法候选 | 功法编号 |
| `*敌人附魔池.json` | 附魔源池引用 | 源池文件名 |
| `*灵兽附魔池.json` | 灵兽附魔源池引用 | 源池文件名 |
| `<道侣编号>-<名称>附魔池.json` | 道侣个人附魔候选 | 附魔编号 |
| `物品-宝石-*.json` | 宝石 | 六位编号 |
| `*敌人宝石池.json` | 宝石源池引用 | 源池文件名 |
| `*灵兽宝石池.json` | 灵兽宝石源池引用 | 源池文件名 |
| `<道侣编号>-<名称>宝石池.json` | 道侣个人宝石候选 | 宝石编号 |
| `物品-灵材-*.json` | 灵材 | `20` 前缀六位编号 |
| `物品-兽宝-<灵兽名>.json` | 灵兽独有兽宝掉落池 | `21` 前缀六位编号 |
| 其他 `物品-*.json` | 普通物品 | 六位编号 |
| `战斗机制/*.json` | 机制 | 六位编号 |

不要在 JSON 根节点再包一层“功法”“宝石”或“道侣”。完整实体文件使用字典列表；只保存编号或源池名的引用池使用字符串列表。个人池中的编号是实体引用，不是重复实体定义。

## 文件池与实体索引

每个内容文件同时产生两种运行视图：

```text
文件名 -> 此文件包含的实体编号或名称        用于资源池
实体编号 -> 唯一实体定义                    用于具体引用和存档
```

同一实体可以出现在多个池中，但同一编号的完整实体定义必须一致。池内重复是否保留，由展开调用方显式选择；实体本身不保存“来自哪个池”。

引用池分成两种根节点形态，均直接使用字符串列表：

```text
道侣个人池 -> 六位实体编号列表
敌人/灵兽阶段池 -> 实体源文件名列表
```

数据服务会在启动时递归展开源文件池，并拒绝悬空编号、悬空文件、类别不匹配、混合引用和循环引用。无法识别的内容文件不能静默跳过。

玩家直接使用全部功法、附魔和宝石源池。264名道侣分别通过个人功法池、个人附魔池和个人宝石池引用稳定编号；敌方修士与灵兽分别使用自己的六阶段定向池。运行时只读取这些实际池，不维护额外清单。

## 内容依赖

- 世界地点引用道侣池、敌人池和灵材池。
- 地图规则引用地势和道路文件；道路引用地点名与地势水平坐标。
- 敌人掉落引用普通物品池和所在地的灵材池；灵兽再按自身完整名称引用独有兽宝池。
- 道侣喜好引用灵材池。
- 功法和附魔引用战斗机制编号。
- 宝石引用战斗属性名。
- `规则/构筑/相冲.json` 引用战斗机制编号并约束功法和附魔组合。

## 修改检查

1. 新内容文件名必须在整个 `内容` 树中唯一。
2. 新编号必须符合 `定义/编号.json` 的类别前缀。
3. 改池文件名时必须全库更新所有池引用。
4. 改机制编号、属性名时必须检查功法、附魔、宝石与构筑规则。
5. 内容可以改展示名称，但数据库和具体引用必须继续使用稳定编号。
