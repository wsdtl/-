# 内容 JSON 关系说明

`内容` 保存世界中真实存在、可以被引用或抽取的对象。内容文件不重新定义编号规则、属性语义或战斗公式。

## 三个内容域

| 目录 | 当前内容 | 详细说明 |
| --- | --- | --- |
| `世界` | 1 个世界、11 个区域、80 个地点、264 名道侣、160 个敌人 | [世界/说明.md](世界/说明.md) |
| `战斗机制` | 80 个机制池文件、1600 个编号机制 | [战斗机制/说明.md](战斗机制/说明.md) |
| `物品` | 普通物品、功法、附魔技能书、宝石 | [物品/说明.md](物品/说明.md) |

## 文件身份就是分类入口

加载器按文件名和位置判定内容类别：

| 文件形式 | 加载类别 | 单项身份 |
| --- | --- | --- |
| `地图规则.json` | 世界 | 文件自身 |
| `世界/<区域>/<区域>.json` | 区域 | 文件名 |
| `世界/<区域>/<地点>/<地点>.json` | 地点 | 文件名 |
| `*道侣.json` | 道侣 | 六位编号 |
| `*敌人.json` | 敌人 | 对象键名称 |
| `功法-*.json` | 功法 | 六位编号 |
| `物品-附魔-*.json` | 附魔 | 六位编号 |
| `物品-宝石-*.json` | 宝石 | 六位编号 |
| 其他 `物品-*.json` | 普通物品 | 六位编号 |
| `战斗机制/*.json` | 机制 | 六位编号 |

不要在 JSON 根节点再包一层“功法”“宝石”或“道侣”。编号内容根节点直接使用数组；敌人使用名称到定义的对象。

## 文件池与实体索引

每个内容文件同时产生两种运行视图：

```text
文件名 -> 此文件包含的实体编号或名称        用于资源池
实体编号 -> 唯一实体定义                    用于具体引用和存档
```

同一实体可以出现在多个池中，但同一编号的完整实体定义必须一致。池内重复是否保留，由展开调用方显式选择；实体本身不保存“来自哪个池”。

## 内容依赖

- 世界地点引用道侣池、敌人池和天材地宝池。
- 敌人掉落引用普通物品池。
- 道侣喜好引用天材地宝池。
- 功法和附魔引用战斗机制编号。
- 宝石引用战斗属性名。
- 构筑规则引用战斗机制编号并约束功法和附魔组合。

## 修改检查

1. 新内容文件名必须在整个 `内容` 树中唯一。
2. 新编号必须符合 `定义/编号.json` 的类别前缀。
3. 改池文件名时必须全库更新所有池引用。
4. 改机制编号、属性名时必须检查功法、附魔、宝石与构筑规则。
5. 内容可以改展示名称，但数据库和具体引用必须继续使用稳定编号。
