# 晓楠修仙

当前版本已经跑通第一个小循环：闭关强化人物并感悟功法，探险连续战斗并培养本命武器。
游戏使用 SQLite 即时事务和分类中文 JSON 配置，不依赖 ORM、Redis、消息队列或万能快照。

## 启动

Windows：

```powershell
cd C:\Users\16841\Desktop\晓楠修仙
start.bat
```

Linux 或 Docker：

```bash
bash start.sh
```

启动脚本会在项目根目录创建 `.venv`，缺少依赖时才安装。默认入口：

- 服务：`http://127.0.0.1:8845`
- QQ webhook：`http://127.0.0.1:8845/qq/events`
- 天道管理台：`http://127.0.0.1:8845/game-console`

本地触发示例：

```powershell
python -X utf8 local.py --user 10001 状态
python -X utf8 local.py --user 10001 地图
python -X utf8 local.py --user 10001 前往 青溪镇
python -X utf8 local.py --user 10001 闭关
python -X utf8 local.py --user 10001 出关
python -X utf8 local.py --user 10001 探险
python -X utf8 local.py --user 10001 结束探险
```

## 小循环

- 闭关和探险固定 60 分钟，每满 10 分钟完成一轮，未满一轮不发轮次奖励。
- 闭关按真实秒数线性恢复血气、精神和体力；满 60 分钟恢复圆满并清除临时战斗状态。
- 闭关获得人物经验，并按轮次概率从全功法池感悟功法。
- 最多同时装配 6 本功法；功法有品级和随机词条，没有等级，同名不能同时装配。
- 探险开始时连续模拟最多 6 轮，回复只展示预计轮数，不提前展示奖励。
- 探险中的资源、临时状态、冷却和丹药消耗跨遭遇继承；战败或未分胜负会停止后续遭遇。
- 提前结束只结算已经满 10 分钟的轮次；满 60 分钟后保留待结算状态，直到玩家主动结束。
- 所有普通物品和功法实例都在纳戒中，按类别每页 50 条，没有容量上限。
- 人物出生在青溪村 `(8, 8)`；所有地点使用唯一整数坐标，任意已登记地点均可按名称即时前往。
- 行路距离按曼哈顿距离 `|横轴差| + |纵轴差|` 计算并展示；闭关或探险期间不能移动。
- 每个探险地点引用一个或多个敌人资源池文件；所引文件先整合为对象池，每轮再按对象权重抽取敌人。
- 地点不配置安全或危险标记，只声明 `可用功能`；提供“修士”的地点才可交谈、赠礼并邀请道侣。
- 道侣首次入队固定生成并保存方向、资质、本命武器、三门功法、三个附魔和三颗宝石；离队再入队不重抽。
- 同行道侣随人物移动并一起进入探险战斗，共享纳戒丹药；闭关同步获得经验和恢复，探险同步培养本命武器。
- 敌对修士拥有等级、本命武器、功法、纳戒和用药决定；镇岳防线及其以北的探险地点通过同层敌人文件引用，
  南部六州的探险地点主要引用灵兽。

## 数据

运行配置按目录分类：

```text
data/rules/人物/*.json
data/rules/修炼/*.json
data/rules/战斗/*.json
data/rules/品级/*.json
data/content/世界/地图规则.json
data/content/世界/<州或区域>/<州或区域>.json
data/content/世界/<州或区域>/<地点>/<地点>.json
data/content/世界/<州或区域>/<地点>/<地点>道侣.json
data/content/世界/<州或区域>/<地点>/<地点>敌人.json
data/content/战斗机制/*.json
data/content/战斗机制/方向/机制-<战斗方向>.json
data/content/物品/功法/功法-*.json
data/content/物品/附魔技能书/物品-附魔-*.json
data/content/物品/宝石/物品-宝石-*.json
data/content/物品/<类别>/物品-<类别>-<用途或来源>.json
```

加载器会递归读取分类目录内的全部 JSON，把同类对象展开到内存对象表；整个 `data` 中的 JSON 文件名
必须全局唯一，同名对象也会直接报告两个来源文件。
随后各领域校验器检查引用、属性、数值范围、触发器和基础战斗效果。配置使用未知机制时，错误会直接指出
文件、字段和效果名。正式规则和内容全部位于 `data`；仓库不再保留另一套设计母本。

功法和所有普通纳戒物品统一归入 `content/物品`，再按功法、丹药、附魔技能书、宝石、灵兽材料、
天材地宝和修行器物分类。`物品-类别.json` 只声明展示顺序；功法继续使用独立实例表和功法专用校验。
附魔、宝石文件同时保存物品底座与战斗能力，加载时直接生成对应纳戒物品，不再维护第二份重复定义。

运行配置采用中文文件名和全中文内容契约：字段名、内容名、属性名、效果类型和触发时机都直接写中文；地点名、
敌人名、物品名、功法名、品级名和词条名本身就是内容 ID，不再经过中英翻译表。旧英文配置不提供
兼容分支，升级内容时必须按当前中文字段填写。Python 类名、函数名和 SQLite 表名仍使用英文，避免
把玩家内容契约与程序内部实现混在一起。

战斗配置按职责拆开：`rules/战斗/属性.json`、`资源.json` 和 `流程.json` 保存基础契约，
`原子能力.json` 声明每种能力的类别、执行器、字段、类型、默认值、嵌套和约束；
`content/战斗机制` 保存可复用机制与词条，`战报.json` 保存战报协议和展示词典。

当前战斗目录包含 264 个真实方向，每个方向各有 9 门功法、9 本附魔技能书和 9 颗宝石。自动审查会剔除
功法名、状态名和机制计量名后比较完整能力树，强制 264 个方向仍然全部不同，不能靠替换名称通过。
功法的主动技能使用全局唯一 `释放顺序`，被动功法与附魔使用全局唯一 `结算顺序`。三类资源统一使用
`提供标签`、`需要标签`、`禁止标签` 和 `互斥组` 校验构筑。道侣抽取 3/3/3，普通敌方修士从随机方向抽取
6/6/6，首领从全池筛选兼容战术后抽取 6/6/6。

每门功法在 `组成` 数组中组合固定属性、主动技能和被动技能，随机词条只保存词条引用。启动时由通用
Schema 校验器递归检查能力树，运行时按 JSON 声明的执行器调度；同一执行器可供多个能力名复用。
所有伤害统一经过命中、暴击、
穿透与防御、增减伤、格挡、护盾和血气流水线。多本功法的主动招式按就绪轮转，不会只使用出生顺序
最靠前的两本。详细边界见 `game/rules/battle/说明.md`。

所有参战对象都以同一个 `CombatantSnapshot` 进入战斗，并由后端明确携带类别和等级。玩家与敌对修士
使用同一套人物成长、功法、状态、冷却、丹药和策略流程；灵兽使用自身属性成长和基础攻击。
本命武器不是物品，不进入纳戒或掉落。奖励仍由玩法组件在战斗外结算。

道侣和敌人资源都紧邻所属地点文件。道侣只属于结交分支，不配置战斗策略、独立纳戒或掉落；敌人只属于
战斗分支。道侣入队后复用人物的闭关恢复与共享丹药资产，不另造一套恢复和独立用药系统。

`content/世界/地图规则.json` 定义世界背景、坐标边界和出生地；州或区域文件只描述辖区，地点文件保存
坐标、可用功能和同层道侣/敌人资源池引用。地点不保存安全或危险字段；`道侣池`、`敌人池` 必须分别与
“修士”“探险”功能同时出现。运行时先展开并整合为对象池，触发遭遇时再从整合池抽取对象。玩家命令始终使用
中文地点名，人物真实位置在数据库中保存为 `x/y`，不保存展示地点名。正式资产保存在
`data/game.db`。天道管理台的短期消息流水保存在 `data/runtime_log.db`，
表名统一使用 `log_` 前缀，每行都有 `created_at` 和 `expires_at`，保留 2 小时且最多 1000 条。

所有进入随机池的修士、敌人、物品、功法、品级、随机词条、附魔和宝石都使用整数 `权重`：综合能力
价值决定权重，伤害、生存、辅助效果或泛用性越好，配置的权重越高，因此更难抽中；实际抽中率与 `1 / 权重` 成正比。例如权重 `20`
的对象约是权重 `40` 对象的两倍常见。`权重` 不参与战斗数值计算。
对象池 `权重` 不写小数。敌人 `掉落.物品池` 直接引用细分类物品 JSON；每次胜利把所引文件整合后按物品
权重抽取一个，再独立抽取品级，引用处不重复配置概率和数量。

`rules/品级/品级-通用.json` 独立定义黄品、玄品、地品、天品、圣品的阶序、抽取权重、能力倍率和价格系数。
功法、附魔和宝石的固定属性、伤害、恢复、护盾、资源与状态辅助效果统一受能力倍率影响；普通物品按
品级分别堆叠，丹药恢复量和评分受能力倍率影响，参考价乘价格系数。阶序可直接支持“至少地品”一类筛选。

## 验证

```powershell
python -m compileall -q game launch message tests main.py local.py
python -m unittest discover -s tests -v
python -X utf8 tools/audit_direction_mechanics.py
python -X utf8 tools/audit_battle_balance.py
```

回归测试使用临时数据库，不会修改正式 `data/game.db`。机制审查结果写入 `log/战斗机制审查.json`；平衡
审查覆盖全部 264 个方向、三槽与六槽、全部品级和真实战斗，结果写入 `log/战斗平衡审查.json`。综合差距
不高于 30% 才通过，超过 50% 拒绝。
