# 战斗基石与执行核心

战斗系统从基石重新开始。旧功法、旧宝石、旧附魔和旧字段不属于兼容目标，也不能反过来限制基石。
当前阶段只定义可组合的战斗语义，并保证每一种已声明语义都有真实执行路径。

## 唯一规则源

战斗规则只来自以下 JSON：

| 路径 | 职责 |
| --- | --- |
| `data/定义/战斗/属性.json` | 战斗属性、边界、精度和含义 |
| `data/定义/战斗/资源.json` | 当前资源与对应上限属性 |
| `data/定义/战斗/事件.json` | 事件事实和允许修改的部分 |
| `data/定义/战斗/原子能力.json` | 能力语法、字段 Schema 和执行器路由 |
| `data/规则/战斗/伤害.json` | 伤害流水线使用的边界常量 |
| `data/规则/战斗/行动.json` | 行动条、冷却和安全上限 |
| `data/规则/战斗/状态反应.json` | 状态组合反应；当前可以为空 |

`foundation.py` 单独加载并校验这些基石，不读取任何功法、宝石、附魔、敌人或道侣内容。Python 不保存
第二份规则表，只实现 JSON 中执行器对应的最小结算语义。

## 时间模型

战斗只有两种时间约束：

1. 行动条决定参战者何时获得主行动。
2. 技能冷却按技能拥有者的自身行动推进，决定该次行动能否使用技能。

不存在蓄势、读条、冷却回合或另一套隐藏时间轴。追加攻击、反击、连击和触发技能都在当前能力链内结算，
不产生新的主行动，也不额外推进冷却和状态持续时间。

## 原子能力

当前 68 个原子能力分为八类：装配、引用、组合、触发、数值、目标、条件和效果。它们覆盖：

- 顺序、条件、随机、遍历、重复、尝试和可回滚事务。
- 固定值、事件事实、资源、状态、技能、历史记录、计量与集合聚合。
- 自身、当前目标、事件角色、双方阵营、关联对象、主人和控制者。
- 伤害、恢复、消耗、转移、状态、行动条、冷却、计量和非资源代价。
- 事件数值、目标、标签、取消和同结算族类型转化。
- 技能修改、复制、触发，效果回放，命名结果和战斗事实。
- 行动意图、判定、战场规则、形态、战术、归属、召唤物和构造物。

功法等二次对象以后只能组合这些能力。确实出现新底层语义时，先扩展 `原子能力.json`，再增加一个对应的
最小执行器和边界测试；不能在具体功法名、状态名或物品名上写 Python 分支。

## 事件链

`事件.json` 当前声明 57 个事件。每个事件分别列出携带事实和可修改项；没有声明的修改会被核心拒绝。
监听器可以观察来源、承受者或行动者，并区分自身、其他己方、任意己方、任意敌方和任意对象。

事件转化不是单纯改名。目前只有 `恢复前`、`获得护盾前`、`资源恢复前` 共享资源获得结算语义，因而允许
互相转化；其他事件不宣称支持类型转化。A -> B -> A 会立即以循环错误终止。事件数值、目标和标签的修改
都会传入最终结算和后续事件。

## 属性与结算

普通攻击威力、技能威力、命中、闪避、暴击、抗暴、暴击伤害、暴击伤害减免、穿透、防御、增减伤、
格挡和破格进入统一伤害流水线。治疗加成与受疗加成、护盾加成与受盾加成分别作用于资源产生方和承受方。
控制状态使用基础控制命中率、控制命中率、控制抵抗率判定，成功后再由韧性缩短持续行动数。

伤害顺序固定为：

```text
原始伤害 -> 命中 -> 暴击 -> 穿透与防御 -> 增减伤 -> 格挡 -> 最低伤害 -> 护盾 -> 血气
```

每段伤害独立记录中间值、护盾伤害、血气伤害和过量伤害。吸血读取实际血气伤害；反伤读取实际承受的
直接伤害。伤害重定向后会按新目标重新计算防御，资源和状态目标重定向也以最终承受者结算。

## 队伍与战斗对象

左右双方都是真正的参战者集合。目标选择、事件阵营关系、行动队列和胜负都读取实时阵营，不把道侣或召唤物
伪装成主角附属数值。主人、控制者和阵营是三个独立字段，战斗中可以分别修改。

召唤物拥有属性、技能、被动、行动条和冷却，可以行动并参与胜负。构造物可以被选择、受伤和摧毁，也可以
持有监听器，但永不行动且不参与胜负。数量上限来自 `行动.json`。主动移除、耐久归零和持续时间结束统一走
一次性退场路径；退场会清理明确声明随来源移除的状态和战场规则，并释放数量名额。

## 事务与安全边界

`事务执行` 失败时会一起还原：

- 所有参战者、队伍归属、资源、状态、技能、库存和行动条。
- 新建召唤物和构造物、战场规则、关联、计量、记录和效果历史。
- 当前事件改写、行动意图、判定覆盖、触发计数和随机数生成器状态。

安全上限全部由 `行动.json` 提供，包括事件链深度、能力链深度、触发技能嵌套、追加攻击、召唤物和构造物
数量。超过深度会明确报错；达到数量或嵌套上限的原子执行失败，不会生成半个对象或遗留部分代价。

## 代码边界

| 文件 | 职责 |
| --- | --- |
| `game/rules/combat.py` | 行动条、行动决策、技能施放和整场循环 |
| `game/rules/battle/mechanics.py` | 原子能力、事件、状态、事务和战斗对象 |
| `game/rules/battle/damage.py` | 单段伤害流水线 |
| `game/rules/battle/models.py` | 战斗输入、运行状态和结构化结果 |
| `game/rules/battle/schema.py` | JSON 能力 Schema 校验 |
| `game/rules/battle/foundation.py` | 基石独立加载和跨文件契约校验 |

战斗核心不读数据库、不发消息、不计算评分，也不结算经验、掉落或灵石。校核、评分和平衡脚本只能放在
`tools/`，其结果不能参与游戏运行、存档身份或战斗裁定。

## 验证

```powershell
python -m unittest tests.test_battle_foundation -v
python -m unittest tests.test_data_loading tests.test_architecture_boundaries -v
```

第一组验证基石原子和真实运行边界；后两组验证数据目录加载与游戏不得依赖 `tools/`。旧二次内容的测试不作为
新核心保留标准，后续应随功法、宝石和附魔的新设计一并重写。
