# JSON 数据核心微服务

`game.core.data` 是核心微服务层的第一个正式成员。它在进程启动时读取一次 `data`，建立只读文档、实体、资源池和世界索引，并向其他微服务提供正式定义数据。

```text
game/app.py
  -> CoreServices.data
  -> JsonDataService.initialize()
  -> JsonDataReader 固定读取 定义/数据读取规则.json
  -> JsonDataReader 按规则唯一匹配并归档全部正式 JSON
  -> GameDataLoader 建立实体、直接编号池和源文件池索引
  -> 校验通用文档形态、编号前缀、池引用和循环引用
  -> FeatureServices 中的玩法微服务通过构造参数取得依赖
```

Python 只固定知道引导文件的位置和标准 JSON 语法。作用域、文件路径模式、数据集、交付数据名、文档形态、实体类别、编号类别、同名池和池引用字段均由 `data/定义/数据读取规则.json` 声明。规则文件也必须由自身的一条规则唯一匹配，从而形成清楚且有限的启动边界。

`cmd` 是触发层，不得直接访问数据服务。玩法微服务通过构造参数取得 `JsonDataService`，且只能从 `game.core.data` 包顶层导入公共契约；`files.py` 与 `loading.py` 属于内部实现。其他服务不得保存或拼接 JSON 路径，应请求规则已经命名的数据集。

```python
from game.core.data import JsonDataService

def load_domain_data(data: JsonDataService):
    foundation = data.dataset("战斗基石")
    technique = data.entity("功法", "400001")
    all_gems = data.entities("宝石")
    identities = data.pool_members(["入微敌人宝石池"], "宝石")
    weights = data.pool_fields(
        ["入微敌人宝石池"],
        "宝石",
        ["权重"],
    )
    return foundation, technique, all_gems, identities, weights
```

直接编号池保存实体编号；源文件池保存其他内容文件名。数据服务递归展开两者并校验类别，资源池微服务只请求候选编号和 `权重`，不会复制整份功法、附魔或宝石定义。

运行期间不扫描、不监听、也不重新加载 JSON。修改正式数据或读取规则后必须重启服务。完整校核、评分和平衡仍属于 `tools`。其他微服务负责解释所属数据集的玩法含义和业务引用，数据服务不替它们做战斗、世界或角色判断。
