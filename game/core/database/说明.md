# 核心数据库微服务

本服务是所有玩法共享的本地持久化边界，不解释角色、物品、战斗或世界 JSON。它负责读取当前状态与位置，并把不同玩家的状态变化和位置变化连同一次幂等事务原子写入 SQLite。

## 表

```text
state_snapshot
  user_id + state_type + state_key  唯一定位一个状态
  state_json                         当前状态正文
  version                            乐观并发版本

committed_transaction
  transaction_id                     一次提交的稳定事务编号
  user_id + request_id               防止QQ或任务重试重复结算
  changes_json                       业务提交摘要与状态版本变化

player_location
  user_id                            玩家地表位置唯一身份
  x + y                              当前地表坐标
  version                            乐观并发版本
  updated_at                         最近位置变化时间
```

数据库不建立账号表、角色表、背包表、功法表或每玩法一张表。QQID就是`user_id`；一般玩家资产通过状态类型和状态键扩展。位置因为存在 `xy -> 多个玩家` 的反向范围查询，使用唯一的结构化位置表和 `(x, y, user_id)` 联合索引，不在人物 JSON 中复制坐标。

## 状态边界

角色、人物行为状态、物品、修行所得、武器和阵法的状态都归属于玩家。角色服务拥有人物资产写入权，人物状态服务拥有人物行为状态写入权；跨领域创建或结算仍把所有变化组成一笔数据库事务。任何命令或玩法不得直接写 SQLite。

普通物品使用 `inventory/<编号>:<品级>`，类别由 JSON 编号定义解析。功法、真意和气机所有权使用 `cultivation_library/<编号>:<品级>`，当前装配仍聚合在 `cultivation/main`；两者分离，换装不消耗所有权。待覆炼器律使用 `law_reserve/<编号>` 并保存数量，本命武器及已覆炼器律聚合在 `weapon/main`。天地玄黄阵法使用 `formation_reserve/<编号>:<品级>` 合并数量，圣品阵法使用 `formation_reserve/<实例编号>` 独立保存真实材料投入。已掌握丹方使用 `knowledge/<编号>`。

## 事务边界

一次业务结算必须把所有相关操作放进同一个 `TransactionCommand`。`StateMutation` 和 `LocationMutation` 都显式携带目标 `user_id`，因此未来多人结算可以在一笔事务中修改多个玩家。创建人物同时写入资产、初始状态、物资和地表位置；战斗奖励同时更新灵石、经验和物品。每项操作带 `expected_version`，任一版本不一致则整笔事务回滚。

读取不使用全局写锁；WAL 下不同连接可以并发读取。写入使用 `BEGIN IMMEDIATE`、进程内写锁和 SQLite 忙等待共同串行。批量状态读取每批最多三百个地址，避免不同 SQLite 构建的绑定参数上限差异。

数据库服务本身不监听 JSON 变化；JSON 更新必须重启进程后生效。数据库也不负责迁移旧业务表或旧人物位置，不保留兼容读取。
