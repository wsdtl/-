# 核心数据库微服务

本服务是所有玩法共享的本地持久化边界，不解释角色、物品、战斗或世界 JSON。它只负责两件事：读取当前状态，以及把一组状态变化和一次已提交事务原子写入 SQLite。

## 表

```text
state_snapshot
  user_id + state_type + state_key  唯一定位一个状态
  state_json                         当前状态正文
  version                            乐观并发版本

committed_transaction
  transaction_id                     一次提交的稳定事务编号
  user_id + request_id               防止QQ或任务重试重复结算
  changes_json                       业务提交摘要与状态版本变化
```

数据库不建立账号表、角色表、背包表、功法表或玩法表。QQID就是`user_id`；玩法通过状态类型和状态键扩展，而不是新增数据库表。

## 状态边界

角色、物品、修行所得、武器和阵法的状态都归属于玩家。后续角色服务是这些玩家资产的唯一写入者：其他领域服务根据 JSON 计算结算结果，再交给角色服务组成数据库事务；任何命令或玩法不得直接写 SQLite。

普通物品使用 `inventory/<类别>:<编号>:<品级>` 状态键；功法、真意、气机和器律使用 `attainment/<类别>:<编号>[:<品级>]`。本命武器和角色修行槽分别聚合在 `weapon/main` 与 `cultivation/main`。阵法是一次性实例，使用 `formation/<实例编号>`，不进入普通背包。

## 事务边界

一次业务结算必须把所有相关状态放进同一个 `TransactionCommand`：例如战斗奖励同时更新灵石、经验和物品；炼制同时扣除材料并生成丹药；装配同时消耗修行所得并替换槽位。每个状态带 `expected_version`，版本不一致则整笔事务回滚。

数据库服务本身不监听 JSON 变化；JSON 更新必须重启进程后生效。数据库也不负责迁移旧业务表，当前地基从两张新表开始。
