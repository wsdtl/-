# 战斗核心微服务

`game.core.combat` 是第二个核心公共微服务。它不自行读取文件，也不拥有角色资产；初始化时消费已经完成加载的 `JsonDataService`，并负责解释战斗基石以及功法、真意、气机对战斗的影响。

```text
CoreServices.data
  -> load_battle_foundation(data)
  -> BattleEngine / DamageEngine / MechanismRuntime
  -> CombatService
  -> CoreServices.combat
```

战斗定义来自：

- `定义/战斗/属性.json`
- `定义/战斗/资源.json`
- `定义/战斗/事件.json`
- `定义/战斗/原子能力.json`
- `规则/战斗/伤害.json`
- `规则/战斗/行动.json`
- `规则/战斗/时序.json`
- `规则/战斗/状态反应.json`
- `规则/战斗/环境.json`
- `内容/战斗机制/*.json` 经 `core.data` 编号索引后展开
- `内容/战场环境/*.json` 经 `core.data` 编号索引后执行
- `内容/阵法/阵法.json` 与 `规则/阵法/炼制.json`
- `展示/战报.json`

其他业务只能从 `game.core.combat` 包顶层使用 `CombatRequest`、`CombatantSpec`、`CombatBuildRef`、`CombatResult` 和 `CombatService`。`engine.py`、`models.py`、`mechanics.py` 等均为内部实现。

```python
result = await combat.execute(
    CombatRequest(
        left_team=(player,),
        right_team=(enemy,),
        seed=123,
        action_limit=2000,
    )
)
```

`CombatantSpec.build` 只携带功法、真意、气机和器律的稳定编号与实例信息，战斗服务自行通过数据服务解析定义。`CombatantSpec.sex` 是由角色业务准备的稳定快照值，只供声明两仪分支的功法作条件判定；战斗核心不推导、修改或持久化性别。战斗核心只处理行动条、技能冷却、事件、监听、状态、伤害、召唤、构造物、阵法和战报事实，不创建角色资产，也不参与评分和平衡。

恢复丹由物品服务转换成 `CombatMedicineSpec` 后随 `CombatRequest.medicine_definitions` 传入，战斗核心只在实时资源低于阈值时执行恢复，不读取物品 JSON。实际服丹会产生带丹药编号、恢复资源、恢复比例和实得数值的`使用丹药后`事件。战丹先由炼药服务完成重复、强度和丹位校验，再以 `CombatStatusSpec` 放入 `CombatantSpec.prepared_statuses`；战斗核心只把其中的机制编号解析为监听节点。纳戒扣除、正式战斗判断和战后清除仍属于未来业务。

阵法通过 `CombatFormationSpec` 以战场级引用传入，不占 `CombatantSpec.build` 装配位。`时序.json` 统一规定四类构筑的来源层级、主动技能排序、事件监听快照和阵法轮转点；圣品阵法只在服务准备阶段按兽宝、灵矿、灵植的数量计算总势，战斗核心执行已经准备好的阵基承载、阵眼冲击和节点传导。

## 战场环境执行

- 承载基准只在开战时求和所有正式参战者的 `血气上限`；护盾、召唤物、治疗和复活都不改写它。
- 每次 `受到伤害后.实际数值` 只计一次；来源身份为 `战场环境` 的伤害不会再推进环境。
- 单次大伤害可连续跨越多个阈值，必须按阶段顺序逐一触发入阶能力。
- 常驻监听使用替换制，阶段变化后只编译当前阶段，不叠加旧阶监听。
- 环境压力以恢复、护盾、判定、冷却、行动条和状态反应为主。环境伤害必须由暴击、闪避、破盾或施法等具体事件触发，不使用全场统一伤害倍率。

## 战报事实保证

- `定义/战斗/事件.json` 是事件全集，`展示/战报.json -> 标准化` 必须逐项声明分类和显示名；初始化时两边少项、多项或残留旧事件名都会直接失败。
- 伤害、恢复、资源消耗和状态变化只按`展示/战报.json -> 标准化.结算事件`指定的最终事件统计，不把前置判定、承受方镜像事件或资源总线事件重复计数。
- 阵法冲击以阵法编号作为事件来源，在战报中拥有独立的承载、余承、冲击、节点、轮转和崩解事实，不归到参战队长的个人伤害。
- 展示时间线只重放结构化事件中的前后数值；最后一个事件后的血气、精神和护盾必须与 `CombatResult` 最终快照一致。
- 功法、真意、气机和器律在战报中保留各自来源类别；机制同时保留稳定编号和显示名称。
